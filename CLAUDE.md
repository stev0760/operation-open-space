# Inner Space port: agent instructions

Faithful Win32 port of **Operation: Inner Space v1.29.08** (Software Dynamics, Win16 NE, 1994–2000). It targets Windows 10/11 natively and Linux through Wine. The port is a C++17 rewrite guided by decompilation of the original and checked against the original running under Wine (the "oracle"). Original game files are never committed. The port reads them from the user's own copy.

The active plan is `docs/PLAN.md`. Feature progress is tracked in `docs/spec/checklist.md`.

## Sources of truth, in priority order
1. **The original's bytes** (`work/` outputs regenerated by `re/isre`) and **oracle digests** (`oracle/digests/`).
2. **The manual:** `ENG_HELP.HLP` and `Eng_help.hl1`, extracted to `work/manual/`. The 2000 file governs v1.29.08; the 1998 file adds the Ship Factory topics.
3. **`docs/re/`**: verified RE facts. **`docs/spec/`**: behaviour spec. **`docs/decisions/`**: our design choices (ADRs).

The Hermes-era docs in `../innerspace-rea/` (read-only archive) are **not** a source. Many of their claims are wrong. `re/TRIAGE.md` lists what was kept, and `docs/re/pitfalls.md` lists the traps.

## Rules for docs
- **Every claim carries an evidence tag:** `[MANUAL topic]`, `[BYTES segN:0xOFF]`, `[ORACLE id]`, `[REF source]` (external documentation), `[DESIGN]` or `[OPEN]`.
  - `[BYTES]` and `[ORACLE]` claims that interpret behaviour need an independent verifier's confirmation before they land in `docs/`.
  - Mechanical facts (counts, hashes, offsets) are proven by tests in `re/tests/`.
- **Docs state current truth.** Git holds the history. Never write "superseded", "withdrawn", "previously" or "now known", and never keep "historical" sections. Dead ends become present-tense rules in `docs/re/pitfalls.md`.
- **One source of truth per topic.** Link to it; don't restate it.
- **Canonical address form is `segN:0xOFF`,** with N the 1-based NE segment number. DGROUP offsets are written `DGROUP:0xOFF`; for `INSPACE.EXE`, DGROUP is seg19. Ghidra `10xx:` addresses, rea dos-com addresses and file offsets are converted with `isre addr`, never mixed into docs.
- **Only the orchestrator edits `docs/spec/checklist.md`.** Within one workflow run, each doc file has one writer.
- **No invented completion percentages.** Progress is checklist status.

## Rules for code and tools
- **RE tools live in `re/isre/`** (Python package + CLI). They take paths as arguments; no absolute paths anywhere in `re/`, `docs/` or `oracle/`. Every tool has tests. `re/legacy/` holds the Hermes-era scripts awaiting refactor; don't extend them.
- **Generated outputs go to `work/`** (gitignored) and must regenerate from `original/` with one command. Only small manifests and indexes are committed, under `re/artifacts/`.
- **Python** runs from the venv at `re/.venv` (python3.9). Run it with `-I` when it reads untrusted files.
- **The port is C++17, Win32 GDI + winmm,** no engine. It builds with MinGW-w64 GCC (`i686-w64-mingw32-g++`, `x86_64-w64-mingw32-g++`), linked `-static`, and later with MSVC.
- **Modernisations get an ADR** in `docs/decisions/` before they are implemented.

## Environment
- **Wine 11.20 (new WoW64, runs Win16):** `/opt/wine/bin/wine`. Prefix: `~/.local/share/wineprefixes/innerspace`. Don't set `WINEARCH`. Use `WINEDLLOVERRIDES=ctl3d=n` so the game's own CTL3D loads.
- **Headless runs:** `Xvfb :99`, then `DISPLAY=:99 WAYLAND_DISPLAY=`. Screenshots: `import -display :99 -window root`. Input: `xdotool`.
- **Parallel oracle runs** each need their own `WINEPREFIX` and `DISPLAY`, because the game allows only one instance.
- **Ghidra 12.1.2:** `/home/cabal/Git/repos/ghidra_12.1.2_DEV`, with JDK `/usr/lib/jvm/corretto21`. The rea MCP is configured with both.
- **Sudo** is passwordless on this host.

## Orchestration
Phases run as Workflow scripts with at most 10 agents each.
- **Roles:** analyst (read-only, works from `isre pack` context packs, never the bulk dumps), verifier (independent, gets only the claim and its addresses), implementer (git worktree when running in parallel), oracle runner, doc writer.
- **Commits:** the orchestrator merges, updates the checklist and commits at the end of each stage.
