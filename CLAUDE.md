# Operation: Open Space: agent instructions

**Operation: Open Space** is a faithful Win32 port of **Operation: Inner Space v1.29.08** (Software Dynamics, Win16 NE, 1994–2000). It targets Windows 10/11 natively and Linux through Wine. The port is a C++17 rewrite guided by decompilation of the original and checked against the original running under Wine (the "oracle"). Original game files are never committed. The port reads them from the user's own copy.

The active plan is `docs/PLAN.md`. Feature progress is tracked in `docs/spec/checklist.md`. `docs/README.md` maps the documents.

**Goal and order:** a faithful port first, then a remaster (M10). Until M10 the fidelity decisions stand as written; ideas for improvements go to the M10 entry in the plan, not into the code. Nothing has been run on real Windows yet.

## Sources of truth, in priority order
1. **The original's bytes** (`work/` outputs regenerated by `re/isre`) and **oracle digests** (`oracle/digests/`).
2. **The manual:** `ENG_HELP.HLP` and `Eng_help.hl1`, extracted to `work/manual/`. The 2000 file governs v1.29.08; the 1998 file adds the Ship Factory topics.
3. **`docs/re/`**: verified RE facts. **`docs/spec/`**: behaviour spec. **`docs/decisions/`**: our design choices (ADRs).

The Hermes-era docs in `../innerspace-rea/` (read-only archive) are **not** a source. Many of their claims are wrong. `re/TRIAGE.md` lists what was kept, and `docs/re/pitfalls.md` lists the traps.

## Rules for docs
- **Every claim carries an evidence tag:** `[MANUAL topic]`, `[BYTES segN:0xOFF]`, `[ORACLE id]`, `[REF source]` (external documentation), `[DESIGN]` or `[OPEN]`.
  - `[BYTES]` and `[ORACLE]` claims that interpret behaviour need an independent verifier's confirmation before they land in `docs/`.
  - Mechanical facts (counts, hashes, offsets) are proven by tests in `re/tests/`.
- **Docs state current truth.** Git holds the history. Never write "superseded", "withdrawn", "previously" or "now known", and never keep "historical" sections. Dead ends become present-tense rules in `docs/re/pitfalls.md`.
- **One source of truth per topic.** Link to it; don't restate it.
- **Canonical address form is `segN:0xOFF`,** with N the 1-based NE segment number. DGROUP offsets are written `DGROUP:0xOFF`; for `INSPACE.EXE`, DGROUP is seg19. Addresses in any other module carry the module name: `ISPACE.DLL seg6:0x643f`, `ISPACE.DLL DGROUP:0x1cd6`. Module names are the installed file names in upper case (`ENG_FX.DLL`, `INSTALL.EXE`); THEWORKS copies take a `theworks/` prefix (`theworks/FACTORY.EXE`). Resources are cited by type and id: `[BYTES ENG_LANG.DLL DIALOG 321]`; a `STRING` tag names the string-table block ((id >> 4) + 1), followed by `id n` outside the tag. Ghidra `10xx:` addresses, rea dos-com addresses and file offsets are converted with `isre addr`, never mixed into docs.
- **Only the orchestrator edits `docs/spec/checklist.md`.** Within one workflow run, each doc file has one writer.
- **No invented completion percentages.** Progress is checklist status.
- **A checklist row is Port `done` when the code has the feature's effect,** not when a key is read or a command is routed; a read without its effect is `wip`. The checklist lags the code: reconcile an area's rows against `src/` at the end of each stage.
- **Wording.** The original install set is "the game" and The Works! is "the add-on"; never write about archives or packaging. A full-version feature the port lacks is "unported", never "restricted". No registration value, pilot name, organisation or personal directory name goes into any file or screenshot.
- **An ADR lands as Proposed** and becomes Accepted only when the user says so.

## Rules for code and tools
- **RE tools live in `re/isre/`** (Python package + CLI). They take paths as arguments; no absolute paths anywhere in `re/`, `docs/` or `oracle/`. Every tool has tests. `re/legacy/` holds the Hermes-era scripts awaiting refactor; don't extend them.
- **Generated outputs go to `work/`** (gitignored) and must regenerate from `original/` with one command. Only small manifests and indexes are committed, under `re/artifacts/`.
- **Python** runs from the venv at `re/.venv` (Python 3.14). Run it with `-I` when it reads untrusted files. Tests: `re/.venv/bin/python -m pytest re/tests` and, as a separate run (the two `conftest.py` files clash in one process), `re/.venv/bin/python -m pytest oracle/tests`.
- **The port is C++17, Win32 GDI + winmm,** no engine. It builds with MinGW-w64 GCC (`i686-w64-mingw32-g++`, `x86_64-w64-mingw32-g++`), linked `-static`, and later with MSVC.
  - Build and test: `cmake --preset mingw-x64 && cmake --build --preset mingw-x64 && ctest --preset mingw-x64` (also `mingw-i686`). CTest runs the Windows test executable under Wine. The `host` preset builds the portable libraries and tests natively, for quick iteration. Warnings are errors (`IS_WERROR`, on by default).
  - The tests read the original from `work/extracted/game` and the assets from `work/assets` (the cache variables `IS_ORIGINAL_DIR` and `IS_ASSETS_DIR`, passed to the tests as environment variables of the same names). Running `is_tests` by hand needs both set; `original/game` is not a substitute. If CTest fails on a path that does not exist, the build cache is stale: `cmake --preset <name> -UIS_ORIGINAL_DIR`.
  - Run the port: `inspace.exe --install <source> [--to <dir>]`, then `inspace.exe [--game <dir>] [--ini <path>]`. Port runs under Wine use a fresh `WINEPREFIX`, never `~/.wine`.
  - Source comments cite the original's addresses in the canonical form, so a reader can go from a line of the port to the bytes.
  - `src/formats/` holds the portable readers (no Win32 calls); tests are doctest (`third_party/doctest/`). Golden tests compare them with the `isre` outputs and skip when `work/` or `original/` is absent.
- **Modernisations get an ADR** in `docs/decisions/` before they are implemented.
- **Faults of the original that depend on CPU speed are fixed, not matched** (ADR 0009). Reads the original leaves undefined follow ADR 0016.
- **Git:** commit with the GitHub noreply identity (check `git config user.email` first), and push only when the user asks. The repository is public.

## Environment
- **Workstation:** Arch Linux, 24 CPUs, 31 GB. `sudo` asks for a password: hand the user one `sudo pacman -S --needed ...` line for system packages and do everything else as the user.
- **Wine 11.0, old WoW64 (Kron4ek `amd64`), runs Win16:** the `ORACLE_WINE` default in `oracle/env.sh` is `~/opt/wine-11.0-oldwow-patched`, a copy of `~/opt/wine-11.0-oldwow` whose `shell.dll16` returns Win16 icon counts (`oracle/digests/wave-0001.md`). Stock new-WoW64 Wine (`~/opt/wine` → `~/opt/wine-11.0`) faults in ISPACE.DLL (`oracle/digests/fault-0001.md`); `~/opt/wine-11.0-patched` carries the fix. The runtimes live under `~/opt`, not `/opt`. Installers: `oracle/wine/`. The system Wine (`/usr/bin/wine`, 11.20, new WoW64) only runs the Win32 test executables for CTest. Prefix: `~/.local/share/wineprefixes/innerspace`. Don't set `WINEARCH`. Use `WINEDLLOVERRIDES=ctl3d=n` so the game's own CTL3D loads.
- **Headless runs:** `source oracle/env.sh; oracle_xvfb` (displays start at `:110`; the desktop is Wayland with Xwayland on `:0`). Screenshots: `oracle_shot out.png`. Input: `xdotool`.
- **Parallel oracle runs** each need their own `WINEPREFIX` and `DISPLAY`, because the game allows only one instance.
- **Ghidra 12.1.2:** the Arch `ghidra` package at `/opt/ghidra`, with JDK `/usr/lib/jvm/java-21-openjdk` (`jdk21-openjdk`); `re/ghidra/run.sh` reads `GHIDRA_HOME` and `JAVA_HOME`.

## Orchestration
Stages run as Workflow scripts with at most 10 agents each, one workflow at a time. Usage is the scarce resource: small work (audits, single fixes, docs) is done inline with no agents.
- **A stage has two parts.** Part A is the RE round: analysts, verifiers, then the docs and fact tests. Part B implements, integrates, reviews, compares with the oracle and fixes.
- **Roles:** analyst (read-only, works from `isre pack` context packs, never the bulk dumps), verifier (independent, gets only the claim and its addresses), implementer (parallel implementers own disjoint files; a git worktree only when their files overlap), oracle runner, comparison runner, reviewer, fixer, doc writer.
- **Models:** set `model` on every agent; the orchestrator's model is never used for a subagent.
  - Opus: analysts, verifiers, fixers, reviewers, and implementers of arithmetic or drawing.
  - Sonnet: oracle and comparison runners, doc writers, fact-test writers, checklist audits, and implementers of plumbing from verified claims.
- **Keep rounds lean:** few analysts with narrow packs; no verifier for mechanical facts that a fact test proves.
- **Agents write their reports to `work/`,** one file each, so a killed run leaves its findings on disk. A workflow that "completes" with empty results was cut off by a usage limit: check the build, fix trivial slips, and relaunch the same script with a note saying what is already on disk.
- **Do not reply to a running workflow agent;** a reply starts a second copy writing the same files. Agents with a structured output escape newlines in it.
- **Commits:** the orchestrator merges, reconciles the checklist, updates the plan and commits at the end of each stage.
