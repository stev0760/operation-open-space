## How Size is changed
- **Three sizes.** The New Game dialog's ZOOM LEVEL combo lists **1/2x, 1x, 2x** and shows 1/2x for INI `Size=0` and 2x for `Size=2` (`ini0/03-newgame.png`, `ini2/03-newgame.png`); `Size` 0, 1, 2 give DGROUP:0x9150 `s` = 4, 3, 2 (`s` = 4 - `Size`). [ORACLE core-0011] [MANUAL Game Settings]
- **Keys in a wave:** **Ctrl + the OEM plus key (`equal` in xdotool) or Ctrl + KP_Add raise Size by one, Ctrl + minus or Ctrl + KP_Subtract lower it by one.** Each press moves one step and is clamped: Ctrl-minus and Ctrl-KP_Subtract at Size 0 and Ctrl-plus and Ctrl-KP_Add at Size 2 change nothing (`lim`). The same keys without Ctrl (`equal`, `KP_Add`) and Alt + `equal` do not change Size. One press in `tr1` (a Ctrl-plus after a Z and a Space burst) did not move the word; the scripts retry until the word moves, and every other press of the 24 timed ones moved it by one step. [ORACLE core-0011]
- **The INI key:** `Size` is read at launch. `SetSize` is written with it. A **Ctrl + / Ctrl - press rewrites `Size` and `SetSize` in `INSPACE.INI` at once** (the file read 1.2 s after the press shows the new value, `pers2`). The New Game dialog's combo starts at the INI value, OK keeps what the combo shows. **An INI `Size=3` is not clamped:** the combo is blank, `s` = 1, and the ship is drawn broken into two halves (`ini3/pre.png`). [ORACLE core-0011]
- **The word DGROUP:0x9158** (`arect`, the number of activity rectangles) moves 1, 2, 4 with Size and position and is not Size's word. [ORACLE core-0011]

## The rebuild at 60 fps (24 presses in `tr3`, `st1`, `wb1`)
- **Timing:** the Size word changes 0.073 - 0.087 s after the key's log line (the press itself is at +0.05 - 0.10 s, so about 25 ms after the key event). The first video frame that shows the new scale follows 0.017 - 0.050 s after the word. No video frame period in any window is longer than 17 ms: **the game does not stall visibly; the rebuild fits in one or two video frames (at most 33 ms).** [ORACLE core-0011]
- **What changes in those frames:** every Size change redraws the play area in one frame (3 000 - 6 500 changed pixels in a mostly black field, the stars and objects relocated: the scene is shown from the same ship position with the view 1/2 or 2 times as wide) and the HUD strip in the same frame (4 500 pixels for 1 -> 0 and 0 -> 1 and 2 -> 1, **31 600 pixels for 1 -> 2** across the HUD's whole width and height of 88 px). [ORACLE core-0011]
- **A black frame:** in 9 of the 24 presses (tr3 4, st1 3, wb1 2; among them 1 -> 2, 2 -> 1, 1 -> 0 and 0 -> 1 changes, and not every press of any kind) **one video frame has no non-black pixel at x < 960**: the whole window except the icon column is black for one frame (`picture/rebuild-1-to-2-black-frame.png`: the frame before, the black frame, the frame after). Between the three Sizes the world position of every object stays: the ship at the same cell origin, the scene scaled about it. [ORACLE core-0011]

## Where Size survives
- **A second New Game in one session:** after Size was set to 2 in a wave (INI `Size=2`), Escape -> Exit (the "exit from the current game back to the intro?" box with Save & Exit, Exit, Cancel; Exit at (511, 421)) -> the intro, the INI still reads `Size=2`; Escape -> Restore Game -> NEW GAME -> New Game's ZOOM LEVEL combo **shows 2x**, and the game starts at Size 2 (`size 2 s 2`, `pers2`, `pers3`). [ORACLE core-0011]
- **A saved game keeps its own Size:** Save & Exit at Size 0 (INI also 0) and Restore (the combo already holds the new save) start the saved wave at Size 0. With INI `Size=2` at launch and the same save, Restore **loads Size 0 over the INI's 2**: the Navigation window shows `size 0`, `s` still 2 (stale), the INI `Size` rewritten to 0 while `SetSize` stays 2; entering the wave sets `s` = 4 and the wave runs at Size 0 (`pers5`: wave word 2 after the restore, size 0, s 4). So the saved header's Size (header +0x171) wins over the INI, and SetSize is not rewritten by it. [ORACLE core-0011]
- **The ambulance visit:** with INI `Size` 2, 0 and 1 the H call took 10 s, 16 s, 16 s to the Options dialog; **the pad scene and the pad ship's picture are the same at every Size**: the crop (440 - 600, 620 - 768) of the dialog screen is pixel-identical across the three runs (0 differing pixels) (`picture/pad-ship-sizes.png`). Size is unchanged after the dialog and after the launch (`size` 2, 0, 1 as before). The wave stays at its Size for the whole visit. [ORACLE core-0011]
- **The next wave through the gate:** not reached. The pilot found no gate beam on screen in 14 tries (about 60 s of flying at Size 0, `pers1`); the Size words did not change during that flight and the INI kept `Size=0`. Whether a gate crossing keeps Size, as the wave-2 entry through seg9:0x6624 would if it leaves DGROUP:0x9156 alone, is [OPEN]; Restore to the saved wave N + 1 is the only next-wave entry measured. [OPEN] [ORACLE core-0011]
- **Quirk:** Escape in a wave opens the exit dialog; the Return that followed closed it with Save & Exit (a Save dialog with an empty name and Cancel, `pers1/p3-after-ok.png`). [ORACLE core-0011]
