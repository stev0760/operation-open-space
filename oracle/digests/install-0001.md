# install-0001: the original installer under the oracle Wine, and the registered game

- **Date:** 2026-10-25. **Host:** Arch Linux, Xvfb 1024×768×24 on `:119`.
- **Runtime:** the default `~/opt/wine-11.0-oldwow-patched` (Wine 11.0, old WoW64), fresh prefix `innerspace9` (`ORACLE_ID=9`), no `Z:`, `WINEDLLOVERRIDES=ctl3d=n`, relay trace with the default profile.
- **Install files:** the user's purchased download `thegame.zip` (25 files, from the author's customer page). Every file is byte-identical to `original/game` except README.TXT, whose copyright year reads 2010. The purchased copy is therefore the v1.29.08 game build; its registration happens at install time, below.
- **Reproduce:** `ORACLE_ID=9 NAME=<name> ORG=<org> oracle/scenarios/install.sh`. It copies the install files to `C:\temp`, runs `INSTALL.EXE` through its dialogs with `xdotool`, stops it, then starts the installed game from `C:\SPACE` and shoots its title. Output in `work/oracle/install/`: `01-warning.png` … `08-readme.png`, `09-title.png`, `steps.txt`, `trace.log` (installer), `game-trace.log`, `INSPACE.INI`, `system.ini`, `files.txt`.
- **Bulk output (gitignored):** `work/oracle/install/`, and the first traced runs in `work/registered/install-try/`. The registration values themselves stay out of git (`work/registered/NOTES.md`).

## The installer runs
- `INSTALL.EXE` completes under the old-WoW64 runtime. The page fault that [smoke-0001](smoke-0001.md) records was under the new-WoW64 runtime. [ORACLE install-0001] [ORACLE smoke-0001]
- The installer busy-waits on `GetCurrentTime` between its screens. An unfiltered `+relay` makes it crawl (the first attempt wrote 700 MB of relay lines in a minute without reaching its first dialog); the default relay profile excludes that call and the installer runs at normal speed. [ORACLE install-0001]
- `winevdm` reports repeated handled `EXCEPTION_ACCESS_VIOLATION`s at the same krnl386 address during the splash. They are Wine's own selector faults, caught by its handler; nothing is lost. [ORACLE install-0001]

## What the installer writes
- **Files** (LZEXPAND, the SZDD sources expand): `C:\SPACE`: INSPACE.EXE, ISPACE.DLL, ENG_LANG.DLL, IGRAPHIC.DLL, FACTORY.EXE, ENG_HELP.HLP, README.TXT, ORDER.TXT and BACKUP.EXE, a byte-for-byte copy of INSTALL.EXE. `C:\SPACE\SHIPS`: MASTER.BOD, MASTER.SHP. `C:\SPACE\SOUNDS`: MAIN.MID, RACE.MID, DEMON.MID, ANTHEM.MID, ENG_FX.DLL, SND_FX.DLL. `C:\windows`: INSPACE.INI (with INSPACE.BAK), INSPACE.SCR, INRUN.AD, WAVEMIX.DLL, WAVEMIX.INI, CTL3D.DLL. Empty `C:\SPACE\GAMES` and `C:\SPACE\RETIRED`. SECURE.DAT is created empty in the source directory and copied nowhere. [ORACLE install-0001]
- **INSPACE.INI [Inner Space]**, in this order: `LocalPath`, `Path`, `ShipPath`, `SndPath` (first to the Windows directory and the temp directory, then to `C:\SPACE\`, `C:\SPACE\SHIPS\`, `C:\SPACE\SOUNDS\`), `Games=GAMES`, `RacePath`, `Dead=RETIRED`, `SoundSystem=3`, `Complex=2` and `FrameRateSet=36` (the difficulty dialog), `Full=1` (the window dialog), `ThePlayer=<name>` and `Detail=3` (after personalization). SYSTEM.INI `[drivers] MSACM.imaadpcm=imaadpcm.acm`. [ORACLE install-0001]
- **Registration, after the personalization dialog.** The writes come from ISPACE.DLL (the relay shows its data segment), as [formats.md](../../docs/re/formats.md#resources-rewritten-in-place) describes from the bytes:
  1. It opens `C:\SPACE\INSPACE.EXE` for writing, walks its NE resource table, writes 10 bytes into `#5500 110` (file offset `0x4b840`) and 50 bytes into `#5000 143` (file offset `0x4b860`, over "Unregistered Copy   ILLEGAL"), and restores the file's DOS date and time (`int 21h` 5700h/5701h). No other game file changes: ISPACE.DLL, ENG_LANG.DLL, IGRAPHIC.DLL and FACTORY.EXE stay identical to the game. [ORACLE install-0001] [BYTES ISPACE.DLL seg10:0x4c68]
  2. It writes SYSTEM.INI `[386Enh] vidsp` and `32BitSP` and WIN.INI `[windows] PDev` (Wine keeps WIN.INI `[windows]` in the registry; the game reads it with `GetProfileInt` all the same). The values differ between two installs on the same day: [formats.md](../../docs/re/formats.md#resources-rewritten-in-place) derives them from random numbers seeded with GetCurrentTime. [ORACLE install-0001] [BYTES ISPACE.DLL seg10:0x5b24]
  3. Earlier, during the splash, ISPACE.DLL reads `C:\temp\INSTALL.EXE` itself twice ("VALID INSTALL DISK"). That is the validation's ordinal 24 command 1, which reads the source INSTALL.EXE's #5500 120 and #5500 110 ([formats.md](../../docs/re/formats.md#resources-rewritten-in-place)). [ORACLE install-0001] [BYTES INSTALL.EXE seg2:0x45cb] [BYTES ISPACE.DLL seg10:0x5416]
  4. The command `INSTALL.EXE` issues after command 9 is ordinal 24 command 0: seg10:0x5612 (a no-op off drives A: and B:), then the #5500 110 writer seg10:0x4b1a and seg10:0x5b24(0x17, x). [BYTES INSTALL.EXE seg2:0x4416 seg2:0x4433] [BYTES ISPACE.DLL seg10:0x490b]
- An install stopped before the personalization dialog (prefix `innerspace7`, first attempt) leaves the game unregistered: it starts as "limited inner space™ / Standard Edition" with the trial-day line and the Press 'R' box. [ORACLE install-0001]

## The registered game
- Start-up reads WIN.INI `[Inner Space] CDDrive` (empty, seg10:0x88db), then ordinal 24 command 2 reads SYSTEM.INI `vidsp` and WIN.INI `PDev` twice, from ISPACE.DLL seg10:0x4f9c and from seg10:0x51b6. The trace holds no `32BitSP` read: command 2 answers 0, so seg10:0x885e never reaches its day block. The state-0 entry and the title make no INI read for the edition, because seg10:0x885e returns at once while DGROUP:0x920c = −1; the title's trial line reads `CDDrive` once more (seg15:0x6fda). [shell.md](../../docs/re/shell.md#intro-and-title-screen) describes the path. [ORACLE install-0001] [BYTES seg10:0x88db seg10:0x8983 seg15:0x6fda] [BYTES ISPACE.DLL seg10:0x5107 seg10:0x5219]
- GetWinFlags returns 0x6c29 (WF_WINNT set) to ISPACE.DLL in the installer and in the game, and neither trace shows an `int 21h` 440Dh media-ID call, so under Wine the values do not bind to a drive serial ([ispace.md](../../docs/re/ispace.md#ordinal-notes), ordinal 24). [ORACLE install-0001] [BYTES ISPACE.DLL seg10:0x4452]
- Title (`09-title.png`): "OPERATION:", "inner space™", " Plus Edition - V1.29.08 Aug 9/2000", the 256-colour hint, the copyright, then "Reg User: <name> - <org>" in place of the trial-day line; no Press 'R' box; "ESC to play - Alt-X to Exit". The main window is created with the title "Inner Space". [ORACLE install-0001]
- The intro and title layout is otherwise the one of [intro-0001](intro-0001.md).

## The free installer, for contrast
- The website's v1.29.07 `inspace.zip` installs with `SETUP.EXE` ("Installer/Upgrader", "Inner Space Demo Install", Ship Factory greyed out, no "PLUS EDITION" on the splash). It asks the same difficulty, window and personalization questions and writes `vidsp`, `32BitSP` and `PDev` the same way, but its installed game starts as "inner space™ / Standard Edition - V1.29.07 Jan 4/2000 / You are on day 1 of your demo trial period" with the Press 'R' box: the personalization step starts the trial clock there and registers the copy only with the sold `INSTALL.EXE`, whose extra write is the `#5500 110` record. The bytes give the reason: `INSTALL.EXE` issues ordinal 24 command 0, while a fresh free install takes ordinal 10 command 9 with mode 0x54; `INSTALL.EXE` reads no `Def` key ([install.md](../../docs/re/install.md#registration)). Run by hand in prefix `innerspace6`; screenshots in `work/registered/shareware-try/`. [ORACLE install-0001] [BYTES INSTALL.EXE seg2:0x43da seg2:0x447b] [BYTES v1.29.07/SETUP.EXE seg2:0x3fda]
