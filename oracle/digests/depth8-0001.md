# depth8-0001: the original on an 8-bit PseudoColor display

- **Date:** 2026-10-24. **Host:** stock Wine 11.0 new WoW64 (`/opt/wine-11.0`), Xvfb 1024×768×**8** (default visual PseudoColor), prefix `innerspace2`, display `:112`.
- **Setup:** the same as [newgame-0001](newgame-0001.md): `--with-ini`, fixture `basic` as `D:`, no `Z:`, and the `version.dll` described there.
- **Reproduce:** `ORACLE_ID=2 DEPTH=8 ORACLE_WINE=/opt/wine-11.0 oracle/scenarios/newgame.sh work/oracle/depth8`. Xvfb must not already be running on `:112` at another depth. The same scenario under the default runtime (old WoW64) at depth 8 reaches wave 1: [newgame-0002](newgame-0002.md), Depth 8.
- **Bulk output (gitignored):** `work/oracle/depth8/` (screenshots, `trace.log`, `digest.md`). The 24-bit run of the same scenario is `work/oracle/newgame/`.

## Device answers
- `GetDeviceCaps` returns BITSPIXEL 8, PLANES 1, SIZEPALETTE 256, NUMRESERVED 20, HORZRES 1024, VERTRES 768 and CAPS1(94) 0. At depth 24 it returns BITSPIXEL 32 and SIZEPALETTE 0. [ORACLE depth8-0001]
- The game reads the static system colours with `GetSystemPaletteEntries(hdc, 0, 10)` and a second call `(hdc, start, 10)`, from ISPACE.DLL seg5:0x36e1/0x3707. `start` is 246 at depth 8 and 6 at depth 24. [ORACLE depth8-0001] How the game derives `start` is [OPEN].

## Title screen
- The game does not issue the "For best results, change Windows to 256 color mode" `TextOut` at depth 8. At depth 24 it does. All other title strings are issued at both depths: "OPERATION:", "limited inner space™", " Standard Edition - V1.29.08 Aug 9/2000", "© 1994-2000 Software Dynamics, inc. All rights reserved.", "You are on day 12087 of your demo trial period.", " Press 'R' to order the full game package " and "ESC to play    -    Alt-X to Exit". [ORACLE depth8-0001]
- On screen the title text is grey and white instead of purple, and the copyright and "Press 'R'" lines are invisible. The SDi logo is missing or drawn in noisy green and yellow (screenshot 20 s after launch). [ORACLE depth8-0001]
- The logo intro calls `TextOut("presents.. ")` repeatedly for 3.0 s, at both depths. The number of calls in those 3.0 s varies between runs: 211–232 in 18 traced Wine runs at either depth and under each Wine runtime, 231 in this one. [ORACLE depth8-0001]

## Palette calls
- Both depths make the same calls: 2 + 3 `CreatePalette`, and 37 `AnimatePalette(hpal, 10, 236, …)`, which animate entries 10–245, from ISPACE seg5:0x441f. [ORACLE depth8-0001]
- Depth 8 adds 7 `GetDIBits` and 7 `RealizePalette` calls returning to ISPACE seg5:0x227c. The dialog `RealizePalette` from seg5:0x20f4 runs 22 times instead of 15. [ORACLE depth8-0001]

## Dialogs and Navigation window
- The Restore Game and New Game dialogs and the Navigation window have the same layout, fields and texts as at depth 24. [ORACLE depth8-0001]
- System colours come out wrong. Dialog and button faces are red, the selection highlight is yellow with unreadable text, and the Navigation window's grey areas are black. The ship preview shows a black-and-white outline instead of the coloured ship. [ORACLE depth8-0001]
- Fixture icons draw with correct colours: ALPHA.EXE's red square shows in the Navigation preview. [ORACLE depth8-0001]
- [OPEN] whether real Windows at 256 colours shows the same system-colour damage, or whether it comes from Wine's PseudoColor palette emulation. The animated range 10–245 leaves the 20 static entries alone, which points at Wine.

- Both faults of [newgame-0001](newgame-0001.md) occur at depth 8 too, so display depth does not cause either fault. Their cause is in [fault-0001](fault-0001.md). [ORACLE depth8-0001]

  - The intro fault at seg6:0x6480, with the intro left to run: an exploratory run without the `version.dll` (`work/oracle/explore/d8-ng1/`, `SKIP_INTRO=0`).
