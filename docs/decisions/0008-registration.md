# ADR 0008: Registration and the installer

- **Status:** Accepted. [DESIGN]
- **Scope:** how the port decides whether the user's copy is registered, what it shows for each edition, and how a copy becomes registered: the port installs the game from the original install files itself. The edition check's code paths stay in [shell.md](../re/shell.md#start-up) and the record layouts in [formats.md](../re/formats.md#resources-rewritten-in-place). [DESIGN]

## Context
- **The sold game is the shipdisk.** The download the author sells today is the v1.29.08 shipdisk byte for byte: 25 files, `INSTALL.EXE` and `INSTALL.INI` with `Def=1`. The free website download is v1.29.07 with `SETUP.EXE` and `Limited=0`. [ORACLE install-0001]
- **Registration is the installer's personalization step.** After Name and Organization, both installers call ISPACE.DLL, which writes three values into `SYSTEM.INI [386Enh] vidsp`, `32BitSP` and `WIN.INI [windows] PDev` and rewrites `INSPACE.EXE #5000 143` with the scrambled "Name - Organization". The sold installer also writes the 10-byte `#5500 110` record (a dword `D` and the install drive), and the installed game then starts as "Plus Edition, Reg User: Name - Organization". The free installer leaves that record empty, and its game starts "day 1 of your demo trial period". The same shipdisk files installed without the personalization step run as "Limited Inner Space". So the gate between the trial and the registered game is the installer's `#5500 110` write, not anything in the game or a code. [ORACLE install-0001] [BYTES ISPACE.DLL seg10:0x4b1a seg10:0x4c68 seg10:0x4dba seg10:0x5b24]
- **The check at run time.** `seg10:0x885e` reads the record and the three values at start-up and derives the edition: on the Windows NT family `D` is a random number and the installer wrote `PDev - vidsp = D mod 653 + 654`; on Windows 3.x and 9x `D` is the install drive's volume serial, compared through `int 21h 440Dh`. The limited version computes its trial day from the local date and `PDev - vidsp`; a mismatch gives "The game isn't valid on this hard drive". The CD edition and the value 3 depend on build constants that are zero in v1.29.08. [BYTES seg10:0x885e seg10:0x8a26-0x8b0a seg10:0x8959-0x89c7] [BYTES ISPACE.DLL seg10:0x4f9c seg10:0x48d2]
- **The Order dialog's Register button** accepts a registration code that the author computed from the serial in `IGRAPHIC.DLL #5500 110` and the day, and on success writes the 35-day values. The author no longer issues such codes. [BYTES ISPACE.DLL seg10:0x78e seg10:0x9b6 seg10:0x5b24] [ORACLE install-0001]
- **A 64-bit Windows cannot run the 16-bit installer.** Without a port of it, a user would register on Windows 9x, XP or Wine and copy the installed directory, and the three INI values would stay behind on that machine. The port exists so that the game runs as designed on modern 64-bit Windows from the files the author sells; a legacy Windows in the loop defeats that. [DESIGN]
- **The port never patches the check** (the project's standing rule), and ADR 0002 names the only writes into the game directory. [DESIGN]

## Decision
1. **The port installs the game from the original install files.** Its install step takes the files the author distributes, a zip or a directory with `INSTALL.INI`, and does what `INSTALL.EXE` does: validates the install set the way the original validates it ([install.md](../re/install.md): `INSTALL.INI` `[Vers] V` must parse, the source directory must be writable, ISPACE.DLL must be present, and the `#5500 110` and `#5500 120` records of the set's `INSTALL.EXE` name a previous install or, when zero, a new one; a zip is unpacked into a directory of its own first), expands the SZDD files into the asset directory with the original's layout, asks the original's questions (components, difficulty and speed, full screen or window, Name and Organization), and writes what the original writes: the INI keys, the `#5000 143` name record and, for an install set that the original registers, the `#5500 110` record, with the three values of the NT branch. The same input gives the same result as the author's installers: the sold download registers, the free download starts a trial. [DESIGN] [ORACLE install-0001]
   - **Which rule applies is decided by the installer the set ships,** recognised by its SHA-256 (ADR 0002 decision 4). The v1.29.08 shipdisk's `INSTALL.EXE` reads neither `Def` nor `Limited` and registers every install: ISPACE.DLL ordinal 24 command 0 writes `#5500 110` into the installed `INSPACE.EXE` and the three values through `seg10:0x5b24(0x17)`; from a hard-disk copy it never writes back into the install set, so the same files register again on the next install. The v1.29.07 `SETUP.EXE` reads `[Vers] Limited` and, with it non-zero, calls ordinal 10 command 9, which writes the three values as a trial start (`seg10:0x5b24(0x54, day)`) and no `#5500 110`. The port applies the recognised installer's rule; an unrecognised installer installs the files and starts a trial. [DESIGN] [BYTES INSTALL.EXE seg2:0x43da] [BYTES v1.29.07/SETUP.EXE seg2:0x3fda] [BYTES ISPACE.DLL seg10:0x4b1a seg10:0x5612 seg9:0x14da]
   - The install step is the only place where the port writes into the asset directory beyond ADR 0002 decision 5, and it writes only its own fresh copy of the files. [DESIGN]
   - The three values go into the `[Registration]` section of the port's own `INSPACE.INI` (ADR 0004), keys `vidsp`, `32BitSP` and `PDev`, not into the Windows directory. [DESIGN]
2. **The port ports the check, read-only.** It reads `#5500 110` and `#5000 143` from the asset directory's `INSPACE.EXE`, the three values from `[Registration]` and, when that section is absent, from `<Windows directory>\SYSTEM.INI [386Enh]` and `WIN.INI [windows]` through the profile functions, so a copy that the original installer registered elsewhere keeps its state when the user copies the two numbers across. It then runs the original's decision procedure on the NT branch: `D` from the record, `PDev - vidsp = D mod 653 + 654`. The result drives every reader of the edition flags: the title lines and colours, the window title, the text pages, the Press 'R' key, the exit path, the Plus-only content table and the saved-game refusal. The port never runs the drive-serial branch: Win32 has no `int 21h 440Dh`, and an install made on Windows 9x also satisfies the arithmetic, because the installer writes the same `PDev - vidsp` on every Windows. [DESIGN] [BYTES seg10:0x885e] [BYTES ISPACE.DLL seg10:0x4f9c seg10:0x5b24]
3. **The 35-day code registration is not ported as a writer.** The Order dialog opens as the original, shows the serial, the day text and the Order Form and More Info buttons (which open the text files with the system's default text editor), and its Register button is disabled with its edit field read-only. The code check (`seg10:0x9b6`) is not implemented. The read side of a 35-day registration (a `32BitSP` equal to `2 vidsp - PDev - 1231`) still works. [DESIGN]
4. **No CD edition.** `WIN.INI [Inner Space] CDDrive` is read and, when non-empty, logged and treated as empty; ordinal 24 command 0x15 is not ported. The build constants that enable the CD and value-3 branches are zero in v1.29.08. [DESIGN] [BYTES seg10:0x8959-0x89c7]
5. **The limited version behaves exactly as the original's:** trial day from the local date, the 14-day and 35-day rules, the Registration Benefits dialog at exit, the Plus Pack counter, and the text the original shows. The port adds no nag and removes none. [DESIGN]
6. **Testing.** The decision procedure is a pure function with doctest cases for the limited shipdisk, a registered record with matching values, a mismatch and the 35-day form; the install step is tested against the original installer's output in `install-0001` (the same files, INI keys and record layouts, with the random values excepted); the oracle comparison runs the port against the registered prefix. No registered record, name or value enters the repository. [DESIGN]

## Alternatives
- **Registering on legacy Windows or Wine and copying the install:** works, and the `[Registration]` fallback of decision 2 keeps it working, but it puts a legacy Windows or a Win16 layer in front of every new user. [DESIGN]
- **Treating every shipdisk as registered:** erases the limited version the author still sells and the behaviour the checklist documents. [DESIGN]
- **A port-side dialog that registers without the install files:** the port would become the thing that registers copies. The install step registers only what the original installer registers, from the same files. [DESIGN]
- **Porting the Register button's code check:** the author issues no codes any more, and a working check in readable source would be a key generator. [DESIGN]

## Consequences
- [install.md](../re/install.md) documents `INSTALL.EXE`; the port's install step is M2 stage 3d with its own oracle comparison against `install-0001`. The installer's Program Manager group (dead DDE code) and its `SYSTEM.INI [drivers]` line are not reproduced. [DESIGN] [BYTES INSTALL.EXE seg2:0x100e]
- Stage 3 of M2 implements the pure decision function, the `[Registration]` section and the readers of the edition flags that the shell reaches; the Plus-only content table `DGROUP:0x2f8a` is applied where M3 and later milestones reach its entries. [DESIGN]
- ADR 0002 gains the install step as a named write into the asset directory. `formats.md` documents the `[Registration]` keys as port-only keys next to the original's. [DESIGN]
- Checklist rows SYS-01 to SYS-04, SYS-11, SYS-12, SYS-13, SYS-14 and SYS-16 describe the behaviour this ADR ports; SYS-15 (CD checks) is out of scope. [DESIGN]
