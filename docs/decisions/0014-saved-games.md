# ADR 0014: Saved games

- **Status:** Accepted. [DESIGN]
- **Scope:** the port's saved-game files (`.sav`, `.ded`, `.don`): their byte layout and block lengths, how the reader validates a file, where the files live, what a failed restore leaves behind, the trial's refusals, and four rules of play that a saved game carries from wave to wave (the refuel cap, negative fuel, the class byte, the repair end value). The layout, the writer and the reader are in [formats.md](../re/formats.md#saved-games); the rules of play are in [core.md](../re/core.md#fuel). This ADR decides only what the port keeps bit for bit and what it changes. [DESIGN]
- **Goal:** the port reads the original's saved games, including a long-running registered game that the original saved on a Windows 98 machine, and writes files that the original can read back. [DESIGN] [ORACLE win98-0001]

## Context
- **A file is up to three blocks back to back with no length fields:** the header (allocated 0x1a9 bytes), the ship roster ((header +0x34 + 1) × 0x7c) and, in a `.sav` only, the directory records (header +0x32 × 0x297) ([Layout](../re/formats.md#layout)). The writer writes `GlobalSize` bytes of each block, and the reader allocates the same sizes and reads `GlobalSize` bytes of each, so a block's length in the file is the host's rounding of its allocation, and a reader on one host fails on a file whose padding is another host's ([Conventions](../re/formats.md#conventions)). [BYTES seg6:0x8aec seg6:0x8b05 seg6:0x8b2f seg6:0x9409 seg6:0x944b seg6:0x94cc seg6:0x950c]
- **The hosts' rounding.** Wine's krnl386 rounds every global block of up to 1 MB up to a multiple of 32 bytes, and its `GlobalSize` returns that size. [REF Wine 11.0 dlls/krnl386.exe16/global.c GLOBAL_Alloc] Windows 3.0 and 3.1 allocate global memory in multiples of 32 bytes: in 386 enhanced mode a block is an even multiple of 16 (32, 64, 96 …), and in standard mode an odd one (16, 48, 80 …). [REF Microsoft KB Q92942, GlobalReAlloc() and GMEM_ZEROINIT Clarified] The 16-bit heap of Windows 95 and 98 has no such statement in the sources at hand; its granularity is [OPEN] until the length of a `.sav` the original wrote on the user's Windows 98 machine is measured.
  - Under 32-byte rounding the header takes 0x1c0 bytes and under standard mode 0x1b0. [DESIGN]
  - The shipped MASTER.BOD (2,288 bytes of records, 2,304 in all) and MASTER.SHP (7,670 and 7,680), which the Factory writes with the same `GlobalSize` rule, rule out exact lengths and 16-byte rounding on the author's machine, but fit 32, 64, 128 and 256 bytes alike. [BYTES MASTER.BOD] [BYTES MASTER.SHP] [BYTES FACTORY.EXE seg4:0x26d4 seg4:0x26dc]
- **No oracle run has measured a saved file yet;** the Wine oracle ran a trial, which writes no `.sav` ([Layout](../re/formats.md#layout)). [ORACLE wave-0001]
- **The reader's checks.** It checks nothing in the header except +0x171 (`Size`, written back to the INI when it differs) and +0x15e: a value below 100 marks an older file, whose roster credit words +0x02 it divides by 10. The roster check (step 8 of [Reading](../re/formats.md#reading)) sets a record's SHP index to 1 when it is not below the SHP count, or for record 0 when seg14:0x455c rejects the ship, for records 0 … DGROUP:0x931a − 1; the last record, DGROUP:0x931a, is not checked. [BYTES seg6:0x95be seg6:0x95e8 seg6:0x98ce seg6:0x98e7 seg6:0x9884 seg6:0x9892 seg6:0x98a4]
- **A failed restore destroys the running game.** The reader frees the running game's roster and directory blocks before it allocates and reads the new ones; a short read then frees whatever the handles hold and zeroes them, and a failed `GlobalAlloc` after the free leaves DGROUP:0x6e24 or DGROUP:0x69f4 pointing into a freed block, without closing the file (steps 4 and 5 of [Reading](../re/formats.md#reading)). [BYTES seg6:0x944b seg6:0x945a seg6:0x9518 seg6:0x9932 seg6:0x94b0 seg6:0x9549]
- **The writer.** It creates the file with `OpenFile` OF_CREATE and writes in place, so a short write leaves a truncated file; when the roster or directory handle is 0 it closes the created file empty ([Writing](../re/formats.md#writing), steps 5, 7 and 8). [BYTES seg6:0x8a78 seg6:0x8acf seg6:0x8ad6 seg6:0x9e66 seg6:0x9eae]
- **Paths.** The saved-game code prefixes `LocalPath`, except the `.ded` purge and the `.ded`/`.don` free-name loop, which prefix `Path`; the Restore Game dialog uses the fixed `GAMES\` and ignores the INI `Games` key ([File locations](../re/formats.md#file-locations)). [BYTES seg6:0x88be seg6:0x89f0 seg6:0x7042] [BYTES ISPACE.DLL seg10:0x1b37 seg10:0x1b55] The port's `Path` is the asset directory, which it never writes, and its `LocalPath` defaults to the INI's directory ([ADR 0004](0004-ini-location.md) decisions 4 and 5, [ADR 0002](0002-asset-source.md) decision 5). [DESIGN]
- **A restored game takes its ships from the roster, not from `MainShip`.** It resumes at wave N + 1 ≥ 2, and seg14:0x0 builds a fresh roster from the INI's ship only when DGROUP:0x91f8 ≤ 1 ([Resuming](../re/formats.md#resuming)). The roster stores SHP indices, not ship names, so a file read against another MASTER.SHP names other ships. [BYTES seg14:0x232 seg14:0x237 seg6:0x9884]
  - seg14:0x2300 reads `MainShip` with the default `EAGLE`, compares it with every SHP record's name, and for a matching record that seg14:0x455c rejects writes `MainShip=TRANSFORMER`; what it gives when no record matches is [OPEN], and this reading awaits a verifier. [BYTES seg14:0x23bf seg14:0x23ec seg14:0x23f9 seg14:0x2407 seg14:0x2420]
- **Rules of play carried by the save** ([core.md](../re/core.md#fuel)):
  - The ambulance refuels the served ship up to the **player's** design tank. [BYTES seg16:0x1776 seg16:0x177a seg16:0x1780 seg16:0x1786]
  - Each 1000 ms tick floors `fuel` at 0 and then, with the cloak on, subtracts 3 without a floor; a computer ship's 150-frame toggle wait can keep the cloak on below 120, so its `fuel` can stand at −3 after a tick ([Consumption](../re/core.md#consumption-seg110x1bcc-every-1000-ms)). [BYTES seg11:0x1d5d seg11:0x1c71 seg11:0x1c83 seg11:0x1c88 seg11:0x1c9e]
  - Roster byte +0x76 (the class 1–10 of a value v) takes, for a v outside every band, the class of the last earlier ship of the same update that matched, or an uninitialised stack value when none did ([Ship roster records](../re/formats.md#ship-roster-records-0x7c-bytes)). [BYTES seg6:0x9ba6 seg6:0x9bf7]
  - The visit's repair phases add 2 every 50 ms to each system below 100 with no clamp, so an odd value ends at 101 while the roster bytes are set to 100 ([The visit](../re/core.md#the-visit-state-6-seg160xcfe)). [BYTES seg16:0x147e seg16:0x150d seg16:0x1527 seg16:0x1630 seg16:0x1653]
- **The trial cannot save or restore.** With DGROUP:0x920c = 0 and DGROUP:0x95bc ≠ 0 the writer writes nothing, a manual save shows string 2324, and the restore's callers refuse with string 2325 ([Names and triggers](../re/formats.md#names-and-triggers), [ADR 0008](0008-registration.md) decision 5). [BYTES seg6:0x8887 seg6:0x88a3 seg6:0x930a] [BYTES ENG_LANG.DLL STRING 146] ids 2324–2325 [ORACLE wave-0001]

## Decision
1. **The file format is the original's.** The port writes and reads the header of 0x1a9 bytes, the 0x7c-byte roster records and the 0x297-byte directory records with every field at the original's offset, width and encoding, cp1252 names included ([ADR 0003](0003-text-and-paths.md)); it adds no field, no magic and no trailer. [DESIGN]
   - **Written block lengths.** Each block is written at its nominal size, (header +0x34 + 1) × 0x7c for the roster and header +0x32 × 0x297 for the directory records, rounded up to the game's granularity and zero-padded. A new game's granularity is 32 bytes, which the original reads back under Wine and on Windows 3.1 in enhanced mode; a restored game keeps the granularity its file was read with (decision 1, reading), so a game brought from the Windows 98 machine is written back in that machine's form. The port does not reproduce a block larger than its nominal size, which the original would write if its in-memory roster or directory block ever outgrew header +0x34 or +0x32 and which its own reader could not read back; whether that happens is [OPEN]. [DESIGN] [REF Microsoft KB Q92942, GlobalReAlloc() and GMEM_ZEROINIT Clarified] [REF Wine 11.0 dlls/krnl386.exe16/global.c GLOBAL_Alloc]
   - **Reading.** The reader takes the nominal sizes from header +0x32 and +0x34, which lie inside the first 0x1a9 bytes, and tries the granularities in a fixed order: 32 bytes, standard mode's odd multiples of 16, then 64, 128 and 256 bytes; the first whose three (or, for `.ded` and `.don`, two) rounded lengths sum to the file's length gives the block offsets. A file that no granularity fits is refused. The padding's contents are ignored. [DESIGN]
   - **Validation,** before any block is read: the file holds at least the header's 0x1a9 bytes; header +0x34 is 0 … 254, since a roster index is a byte with 0xff for a free slot; header +0x32 of a `.sav` is 1 … 98, the records a 64 KB block holds and the bound of [ADR 0012](0012-filesystem-walk.md) decision 3 (the original's `GlobalAlloc` of 0 bytes fails); header +0x2a, the current directory record, is below header +0x32; and the pilot name holds its NUL within its field +0x04 … +0x17 (decision 9). A refused file is a failed restore (decision 2). [DESIGN] [BYTES seg6:0x9c03 seg6:0x94b0 seg6:0x9645-0x9655 seg6:0x975b-0x9764]
   - **The original's own checks stay as they are:** the `Size` write-back of +0x171, the roster check of step 8 (with decision 7's addition), and the version rule of +0x15e (below 100 divides the roster credit by 10). The Restore Game description prints string 311 + (+0x15e − 100) as the original does, also for a value outside 100 … 103. [DESIGN] [BYTES seg6:0x95e8 seg6:0x98ce] [BYTES seg10:0xa184]
   - **Where the files live:** `LocalPath` + `Games` + `\` for `.sav` and `LocalPath` + `Dead` + `\` for `.ded` and `.don`, with `LocalPath` resolved by [ADR 0004](0004-ini-location.md) decision 5 (by default `%APPDATA%\Inner Space\`). The `.ded` purge and the free-name loop use `LocalPath` where the original uses `Path`: the port's `Path` is the read-only asset directory. When `Path` equals `LocalPath`, as in the original's regenerated INI, the result is the original's. The Restore Game dialog keeps its fixed `GAMES\`. A game from another machine is played by copying its `GAMES\` and `DEAD\` files under `LocalPath`, with that machine's MASTER.SHP and MASTER.BOD under `ShipPath`. [DESIGN] [BYTES seg6:0x7042 seg6:0x89f0] [BYTES ISPACE.DLL seg10:0x1b37]
   - **Writing is atomic.** The writer writes a temporary file beside the target and replaces the target with `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`, as [ADR 0004](0004-ini-location.md) decision 8 does for the INI; a short write returns 0 as the original's does but leaves the previous file whole. When the roster or directory handle is 0 the writer returns 0 and leaves the previous file, where the original leaves an empty one; when the game reaches that path is [OPEN]. [DESIGN] [REF Win32 SDK, MoveFileEx] [BYTES seg6:0x8acf seg6:0x9eae]
2. **A failed restore leaves the running game alone.** The port reads the header, the roster and the directory records into new blocks and validates them (decision 1); only when every read and check has succeeded does it free the running game's roster and directory blocks and install the new ones, and then apply steps 6 to 10 of [Reading](../re/formats.md#reading). On any failure it closes the file, frees the new blocks and returns 0 to the caller, which responds as the original's caller does to 0. Step 1 (the new game id and start date) runs before the open, as in the original, so a failed restore still changes them. The difference from the original is only what the running game holds after the failure: the original's game is left without a roster or directory records, or with pointers into freed blocks, which is data corruption. [DESIGN] [BYTES seg6:0x933f seg6:0x944b seg6:0x9518 seg6:0x9549]
3. **The refuel cap keeps the player's tank.** A served computer ship is filled to the player's design tank: the rule is visible in the other ships' fuel, the oracle can compare it, and it corrupts nothing, since a wave start with a roster record caps `fuel` at the ship's own tank. The oracle comparison of a computer ship's visit matches the bytes. [DESIGN] [BYTES seg16:0x1786 seg14:0x1915 seg14:0x1919]
4. **Negative fuel stays.** A computer ship's `fuel` can stand at −3 after a tick, and the next tick's floor brings it back to 0 before subtracting again, so the word never runs further down; the auto-repair test (`fuel` > 90), the refuel price ((tank − `fuel`)/7) and the roster byte `fuel`/40 take −3 as the original's do. The port keeps the signed 16-bit word and its arithmetic, and the oracle comparison of fuel matches the bytes. [DESIGN] [BYTES seg11:0x1c71 seg11:0x1c88 seg11:0x1edc seg16:0x4d6b seg6:0x9b00]
5. **The class byte keeps its stale value.** Roster byte +0x76 takes the class of the last earlier matching ship of the same update for a v outside the bands, as the original does; a rich ship (v ≥ 114) or one in debt (v < 0) is common in a long game, so the carry is reproduced exactly. Where no earlier ship matched, the original stores an uninitialised stack value, which a Win32 build cannot reproduce; the port stores 0, as [ADR 0013](0013-wave-drawing-and-input.md) does for the uninitialised flame local. A byte comparison of a saved roster against the oracle excludes +0x76 in that case only. [DESIGN] [BYTES seg6:0x9ba6 seg6:0x9bf7]
6. **The repairs end at 101.** The visit's phases add 2 with no clamp, so an odd system value ends at 101 in the ship record while the roster bytes read 100; the value is visible in the shape line, the header's +0x15e and the next damage, and the oracle can compare it. The port keeps it. Any reader of the system words that would index a table with 101 is guarded where the implementation finds one, with a `[DESIGN]` tag at its site. [DESIGN] [BYTES seg16:0x150d seg16:0x1653 seg16:0x1014 seg6:0x9131]
7. **Ships the installed files lack.** The roster check of step 8 stays: an SHP index not below the SHP count becomes 1, and so does record 0's when seg14:0x455c rejects its ship, over records 0 … DGROUP:0x931a − 1. The port also applies the bounds part (index not below the count becomes 1) to the last record, which the original leaves unchecked and would read past the SHP table with; that changes nothing for a file whose indices are in range. A restored game never consults `MainShip`. For a new game whose `MainShip` names no record of the installed MASTER.SHP, the port follows seg14:0x2300 once its no-match result is read and verified; an index outside the table from that path becomes 1, as the roster check gives, with a log line. The port does not detect a roster read against a different MASTER.SHP: the file holds indices, not names. [DESIGN] [BYTES seg6:0x9884 seg6:0x98a4 seg14:0x2300] [OPEN]
8. **The trial's refusals stay** ([ADR 0008](0008-registration.md) decision 5): in the limited trial the writer writes nothing, the manual save shows string 2324, the automatic and the `.ded`/`.don` saves fail silently, and the restore's callers refuse with string 2325; the demo's `demogame` keeps its own rule. A registered game copied into a trial's `LocalPath` is not restored. [DESIGN] [BYTES seg6:0x8887 seg6:0x88a3 seg9:0x31e5] [BYTES ENG_LANG.DLL STRING 146] ids 2324–2325 [ORACLE wave-0001]
9. **Failures leave no damage behind.** [DESIGN]
   - **Saving.** A failed save leaves no empty or truncated file: the port writes nothing at the target until every block is ready and written in full (decision 1, "Writing is atomic"), and every failure path closes the file it opened. The original leaves an empty file when its header lock fails or a roster or directory handle is 0, and a truncated one after a short write ([Writing](../re/formats.md#writing), steps 6 to 8). [BYTES seg6:0x8aa4-0x8ab9 seg6:0x8ac8-0x8adb seg6:0x9eae]
   - **The score list.** The score-list builder skips a file it cannot open or that yields fewer than 0x26 bytes and goes on with the next one. The original ends the scan at such a file, leaving the champions table empty, DGROUP:0x93a2 stale and the file open ([Score list](../re/formats.md#score-list), step 3). [BYTES seg6:0x6752 seg6:0x6754 seg6:0x6777 seg6:0x6779 seg6:0x7039]
   - **The reader's bounds.** The reader refuses a file whose header +0x2a is not below +0x32, because the original sets byte +0xad of directory record +0x2a without a check and so writes outside the directory block, and a file whose pilot name has no NUL within +0x04 … +0x17, because the original's unbounded lstrcpy then copies the dates and the tables after it into the pilot buffer ([Reading](../re/formats.md#reading), step 7). These are decision 1's validation. [BYTES seg6:0x9642-0x9655 seg6:0x975b-0x9764]

## Alternatives
| Alternative | Verdict |
|---|---|
| A port-defined save format (versioned, with lengths and a checksum) | Rejected. The original could not read it, the user's Windows 98 game would need a converter, and the score list and the Restore Game preview read the original's header. [DESIGN] |
| Exact block lengths with no padding | Rejected. The original's reader fails on a file without its host's padding. [BYTES seg6:0x9409 seg6:0x944b] |
| Always 32-byte padding, whatever the file read | Rejected for a restored game. If the Windows 98 machine rounds differently, a game written back there could not be restored by the original; keeping the read granularity costs one value per game. [DESIGN] |
| Reproduce the destructive restore | Rejected. It leaves pointers into freed memory, a crash on Win32, and no player can rely on losing a game to a damaged file. [DESIGN] |
| Clamp the repairs at 100, floor the fuel at 0, cap the refuel at the served ship's tank | Rejected. Each is visible and oracle-comparable and none corrupts data; the default is the original's bytes. [DESIGN] |
| Write `.ded` files under `Path`, as the original | Rejected. The port's `Path` is the asset directory, which ADR 0002 keeps read-only. [DESIGN] |

## Consequences
- M4 stage 3 implements decisions 1, 2, 7 and 8 in the saved-game reader and writer (a portable reader and writer under `src/formats/` with doctest cases for each granularity, a refused length, a refused count, the version rule and the swap on failure), and stages 1 and 3 keep decisions 3 to 6 in the visit and the tick. [DESIGN]
- The acceptance run needs a registered oracle prefix: a save in wave 1, the file's length (which settles the Wine side of decision 1 against the expected 0x1c0 + roster + directory), a restore and the briefing title. The length of a `.sav` from the user's Windows 98 machine settles that host's granularity; until then the reader's order of decision 1 covers it. [DESIGN] [OPEN]
- A verifier confirms the seg14:0x2300 reading of Context and reads its no-match result before decision 7's new-game rule is implemented. [DESIGN]
- formats.md's [OPEN] on the Windows 3.x granularity can cite KB Q92942; its doc writer owns that change. [DESIGN]
- The oracle comparison excludes, for a saved file: the padding bytes, roster byte +0x76 where no earlier ship matched (decision 5), and the game id and dates, which come from the clock. [DESIGN]
