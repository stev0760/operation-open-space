# ADR 0005: Help

- **Status:** Accepted. [DESIGN]
- **Scope:** the static manual that F1, F2 and the Help menu open. The game's own dynamic help window (`IS_HELP`, checklist WIN-42 to WIN-45) is M8 and is not WinHelp. [DESIGN]

## Context
- **The original calls WinHelp** with the file `<Language>_HELP.HLP` and a context id per menu item or key. The Help menu items 0xc9 to 0xcb and the keys F1 and F2 reach seg2:0x190a with the context arguments 0x1c, 0 and 5 ([globals.md](../re/globals.md#wm_command-handler-seg20x13b2)). [BYTES DGROUP:0x113] [BYTES seg2:0x190a] [MANUAL Contents]
- **The file is WinHelp 3.1, uncompressed.** `isre hlp` reads it completely and writes it to `work/manual/` as markdown ([re/README.md](../../re/README.md)). The 2000 file holds 38 topics and the 1998 file 41, each with its context ids, help-map id, keywords, hotspots and bitmaps. [DESIGN]
- **Windows 10 and 11 cannot show it.** `WinHlp32.exe` is not part of them, and Microsoft publishes no download for them. [REF Microsoft KB 917607]
- **The port ships no original content** (ADR 0002), so a converted manual cannot be bundled. [DESIGN]
- **WinHelp opened its own window** beside the game, so the manual never shared the game window. [REF Win16 SDK WinHelp]

## Decision
1. **The port reads the HLP at run time** from the asset directory, through a C++ reader in `src/formats/hlp` that ports `isre hlp` and is golden-tested against `work/manual/`. [DESIGN]
2. **It shows topics as HTML in the user's browser.** On the first help request it writes every topic to `<INI directory>\help\<Language>\` (ADR 0004), one HTML file per topic with its bitmaps as PNG. It then opens the requested topic with `ShellExecuteW`. It writes the set again when the HLP's SHA-256 changes. [DESIGN]
3. **Context ids map as WinHelp mapped them,** through the file's context map, so F1 and each Help menu item open the topic the original opened. An id the map lacks opens Contents. [DESIGN]
4. **Hotspots become links** between the exported pages, and the keyword search becomes an index page. The reader's documentation lists any macro or external jump the file holds as [OPEN]. [DESIGN]

## Alternatives
- **A viewer window inside the port** (RichEdit or custom drawing): closer to WinHelp's look, but inline bitmaps and hotspots need an OLE or custom layout layer. Possible later without changing decisions 1 and 3. [DESIGN]
- **Bundling converted HTML:** ships the manual's text and pictures, which ADR 0002 rules out. [DESIGN]
- **Starting `WinHlp32.exe`:** absent on the target systems. Wine's `winhlp32` exists, but only on Linux. [DESIGN]

## Consequences
- M2 adds `src/formats/hlp` with tests, an HTML writer and the context map. `isview` can show the manual through the same reader. [DESIGN]
- Checklist rows SYS-20, SYS-21, KEY-08 and KEY-09 describe the behaviour this ADR ports. [DESIGN]
