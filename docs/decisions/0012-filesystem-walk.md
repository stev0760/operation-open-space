# ADR 0012: Filesystem walk and icons

- **Status:** Accepted. [DESIGN]
- **Scope:** what the port reads from the player's disk for the Navigation window and the wave set-up, how it bounds that against modern volumes, and where it takes the icons it draws. [DESIGN]

## Context
- **The original walks the chosen drive with DOS calls.** The New Game drive list probes `C:` to `Z:` with `_chdrive` and a volume-label `findfirst` on each; the Navigation tree enumerates `X:\*.*` with attribute 0x15 (directories, no hidden entries) one level ahead of the expanded node, probing `<sub>\*.exe` to decide whether a directory is expandable; the file pane and the wave set-up enumerate `<dir>\*.exe` then `<dir>\*.dll`; the only file contents read are icon resources, through `SHELL.ExtractIcon` with index −1 for the count and one call per index. Nothing is loaded or run, and nothing is written outside the game's own INI and save directory ([nav.md](../re/nav.md#filesystem-calls)). [BYTES seg6:0x37ca seg6:0x4748 seg6:0x45be seg6:0x5524 seg6:0x4190 seg9:0x0] [BYTES ISPACE.DLL seg10:0x2104]
- **The names are 8.3.** Every enumerated name comes from `int 21h` find calls, so the tree, the sort, the directory records and the 100-byte path buffer all assume short names; the code has no depth or count limit beyond that buffer. [BYTES seg6:0x4118 seg6:0x37ca] [BYTES DGROUP:0x6990] [OPEN]
- **The order is the volume's.** The root and top-level rows are sorted by the listbox, but children and the file walk keep the enumeration order, and the icon preview is the first file in that order. [BYTES seg6:0x4f46 seg6:0x420a]
- **Icons are drawn as 32×32 `DrawIcon` renders on black.** The original keeps a 32×32 cell per icon and tests it for uniform colour; Win32 `ExtractIcon` returns `SM_CXICON`-sized icons, which are larger at high DPI, and Wine's `ExtractIcon16` miscounts without a patch (`wave-0001`). [BYTES seg9:0x1d2 seg9:0x1e0 seg9:0x8da] [ORACLE wave-0001]
- **A 1994 walk meets modern volumes:** network shares that hang, removable drives without media, junctions and symbolic links that loop, paths longer than 100 bytes, volumes without 8.3 names, and user directories with thousands of entries. [DESIGN]

## Decision
1. **The same calls, through Win32.** The port enumerates with `FindFirstFileW`/`FindNextFileW` exactly where the original calls `findfirst`/`findnext`, with the same patterns and the same attribute filter (directories only where the original asks for 0x15; hidden and system entries excluded where the original's attribute excludes them; names beginning with `.` skipped), and probes exactly what the original probes, in the original's order (the tree one level ahead, the file pane `*.exe` then `*.dll`). It never calls `LoadLibrary`, `ShellExecute`, `CreateProcess` or `OpenFile` on a user file. [DESIGN] [BYTES seg6:0x37ca seg6:0x5524 seg9:0x0]
2. **Drives.** The drive list shows every drive of `GetLogicalDrives` from `C:` to `Z:`, as the original's probe does. Fixed drives and removable drives with media are probed for their label as the original does; a `DRIVE_REMOTE` drive, a removable drive without media or a drive that `GetDriveType` reports as unknown is listed with the original's `Unknown_HD` label without being touched, and is probed only when the player selects it, so a dead share never blocks the dialog. A drive whose root `GetDriveType` reports as missing (`DRIVE_NO_ROOT_DIR`) is skipped, as the original skips a drive whose `_chdrive` fails. The original's `_chdrive` is not reproduced; the port keeps its own current directory. [DESIGN] [BYTES ISPACE.DLL seg10:0x2104]
3. **Bounds.** A directory whose full path would exceed the original's 100-byte buffer is shown but not expandable; a directory entry with `FILE_ATTRIBUTE_REPARSE_POINT` is shown as the original would show a directory but never entered or probed; a directory walk stops listing after 4096 entries; when the 98 directory records are all taken, Enter is refused and nothing is handed to the briefing. The original has no such limits and overruns its buffer instead; what it does on the 99th record is not verified. [DESIGN] [BYTES DGROUP:0x6990] [BYTES seg6:0x3775] [OPEN]
4. **Names and order.** The port uses the 8.3 alias (`cAlternateFileName`) when the volume gives one, and otherwise the long name upper-cased and cut to the 8.3 form the original's buffers would hold, with a Windows-style `BASE~N` tail when the cut name is already taken in that directory (N the first free number, assigned from one listing of the directory that the port makes for itself and does not log, stable for the same long name), so the tree text, the record paths and the completion matching keep the original's shape and two long names never share a row. Children and files keep the `FindFirstFile` order, as the original keeps the volume's order; the root and top-level rows are sorted as the listbox sorts them. The fixture drive `D:` (`oracle/fixtures`) is the test world, and comparisons with the oracle run on the same fixture. [DESIGN] [BYTES seg6:0x4118 seg6:0x4f46]
5. **Icons from the port's own reader.** The icon count and the per-index 32×32 images come from `src/formats/icon` reading the NE or PE resource directory of each `*.exe` and `*.dll`, never from the shell: the count is the number of `RT_GROUP_ICON` resources, as `ExtractIcon(−1)` counts, and a file that is not a valid NE or PE module counts 0. For each group the reader takes the 32×32 member whose colour depth best fits the display and renders it over a black cell as the original's `DrawIcon` does; a group without a 32×32 member is scaled to 32×32 from its nearest size. A file with no icon still counts one and shows the original's program-name placeholder, as `ExtractIcon(path, 0)` does for it; the count queries on the root and the built-in rows add 0. The reader reads the MZ and PE headers and the section table (1 MB at most), then only the section that holds the resource directory (64 MB at most; a resource outside that section gives no cell); an NE module is read whole up to 16 MB. A group member is chosen from its header before anything is decoded, a member over 256 pixels a side is skipped, and a hostile resource directory (names beyond 2^20 UTF-16 units, entries beyond 2^20) counts 0. The reader never throws into the window: anything it cannot read counts 0. The Navigation window draws the cell in true colour, the member choice takes 8 bits per pixel as the display depth (ADR 0007), and a 32-bit member is blended over black by its alpha. The briefing's icon strip draws the same cells. [DESIGN] [BYTES seg9:0x156 seg9:0x278] [BYTES seg9:0x1d2 seg9:0x1e0] [REF Win16 SDK ExtractIcon]
6. **Own files only.** The port's own writes stay where ADR 0004 puts the INI and the saved games (`demogame.sav` is deleted there, as the original deletes it under `LocalPath`); the dead `RadarLeft` and `RadarTop` keys are still read and written back. [DESIGN] [BYTES seg6:0x92b8]

## Alternatives
- **`ExtractIconEx` or `SHGetFileInfo`:** gives the shell's icon at the system size and follows the shell's rules for non-module files; the original's 32×32 cell and count rule would need adjusting, and the Wine patch shows how fragile the shell path is. [DESIGN]
- **A fully sorted tree:** stable across volumes but not what the original shows on the same disk. [DESIGN]
- **No bounds:** faithful, and a hang or a crash on a modern disk. [DESIGN]

## Consequences
- M3 stage 1 implements decisions 1 to 6 in `src/nav/` (a portable walker behind an interface the tests drive with an in-memory tree) and `src/formats/pe` and `src/formats/icon_source` (the count and the 32×32 cell, with golden tests against the fixture programs and `INSPACE.EXE`), for the Navigation window, the New Game drive list and the briefing's icon strip; stage 2 reuses the reader for the wave set-up and moves the briefing's own file enumeration behind the walker. [DESIGN]
- On the oracle prefix the port lists the media-less CD device `E:` as `Unknown_HD`, where the original's `_chdrive` fails and the drive is absent from `newgame-0002` shot 09; the difference is accepted. With the port's own reader the icon counts on the fixture (tools: 4 icons in 2 files) match the patched runtime, not the unpatched `newgame-0002` run. [DESIGN] [ORACLE newgame-0002] [ORACLE wave-0001]
- The wave's drawing model and the polled keys are [ADR 0013](0013-wave-drawing-and-input.md). [DESIGN]
- Checklist rows NAV-01 to NAV-10 and NAV-13 describe the behaviour this ADR ports. [DESIGN]
